## 三、线程冲突问题

### 3.1 **[严重] ContextManager 的 set/update/append_to_list 无锁修改共享 dict**

[context_manager.py:44-57](file:///e:/Desktop/desktop/work/coding/bines/refactoring/thinking/workflow/context_manager.py#L44) — `_get_ctx()` 在锁内创建/获取 dict 引用后释放锁，随后 `set()`、`update()`、`append_to_list()` 在**无锁**状态下修改该 dict。

```python
def set(self, key: str, value: Any, thread_id: str | None = None) -> None:
    ctx = self._get_ctx(thread_id)  # 获取 dict 引用，锁已释放
    ctx[key] = value                # 无锁修改
```

**风险**：如果两个线程同时操作同一个 thread_id 的 context（理论上不应发生，但 `send_msg` tool 从 smolagents 执行上下文调用 `append_to_list`），可能出现数据竞争。`append_to_list` 的 read-modify-write 尤其危险。

### 3.2 **[严重] SQLite 连接无序列化保护**

[workflow.py:90-91](file:///e:/Desktop/desktop/work/coding/bines/refactoring/thinking/workflow/workflow.py#L90) — `sqlite3.connect(..., check_same_thread=False)` 允许多线程访问，但 `_prune_checkpoints()` 中的 DELETE + COMMIT 操作**无任何锁保护**。

Python `sqlite3` 文档明确指出：`check_same_thread=False` 时，**写操作需要用户自行序列化**以避免数据损坏。多个线程同时执行 `_prune_checkpoints` 可能导致数据库损坏。

### 3.3 **[中等] threading.Lock 用于 async 代码**

[napcat_connection.py:66](file:///e:/Desktop/desktop/work/coding/bines/refactoring/thinking/napcat_server/napcat_connection.py#L66) — `self._task_lock = threading.Lock()` 在 async 方法 `_handle_debounce` 和 `_debounce_callback` 中使用。虽然当前锁区间内无 `await`，不会死锁，但若未来有人在锁内添加 `await`，将导致事件循环阻塞。应使用 `asyncio.Lock`。

### 3.4 **[中等] Workflow 超时后线程池 worker 仍在运行**

[workflow.py:184-194](file:///e:/Desktop/desktop/work/coding/bines/refactoring/thinking/workflow/workflow.py#L184) — 超时后 `future.cancel()` 对已启动的 `ThreadPoolExecutor` 任务无效（Python 文档：如果任务已开始运行则无法取消）。实际 worker 线程继续执行，LLM 调用仍在进行，造成**资源泄漏**。`cancel_event.set()` 是唯一的停止信号，但 workflow 节点只在入口检查，长时间 LLM 调用期间不会响应。

### 3.5 **[中等] debounce 取消旧 task 后底层线程不停止**

[napcat_connection.py:96-103](file:///e:/Desktop/desktop/work/coding/bines/refactoring/thinking/napcat_server/napcat_connection.py#L96) — `_handle_debounce` 中取消旧 task 时，`cancel_thread(thread_id)` 设置 cancel event，`old_task.cancel()` 取消 asyncio Future，但 `run_in_executor` 的底层线程继续运行直到完成或超时。
