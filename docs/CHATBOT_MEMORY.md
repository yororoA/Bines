# ChatBot 记忆模式

所有渠道使用 MemoryService。默认 Docker 模式下，完整模式与纯 QQ 模式均由独立的 Memory Server 持有 `memory.db` 和 Chroma 向量索引，网关通过远端服务读写记忆。宿主机纯 QQ 模式在没有 Memory Server 时才退回网关内置的词面检索。数据目录由 `.env` 中的 `BINES_MEMORY_DIR` 指定，默认 `thingking/memory_data`。

QQ 原始消息、事件队列、回复轮次和工具发送回执放在独立的 `gateway.db`。网关确认记忆服务提交后才标记同步成功，重启时继续同步，通过来源标识去重。启动时会识别旧 NapCat `memory.db` 的表结构，先迁移为 `gateway.db`，再创建新版记忆库。

## 每轮回复

1. 从真实 OneBot 事件计算机器人账号、用户和群号；正文中的身份声明不改变权限。
2. 按当前会话补取最多 30 条 NapCat 历史，去重后持久化到同步队列。前台只等待当前会话近期窗口、可信当前批次和可见范围内的待撤回记录，其他积压由后台处理。
3. 读取最近 30 条会话记录、较早情节摘要、相关长期事实和记忆，以及当前个人状态。引用 ID 从原始消息附带。
4. 人格和场景提示词统一由 `persona.yaml` 与 `prompt_builder` 生成。QQ 输入、引用、图片观察和工具结果作为数据处理。
5. 回复确认发送成功后才记录 assistant；结果不确定时保留回执并暂停，禁止自动重复发送。

QQ 同一主体的连续输入先经过原有短聚合；语义明显未完时，Bines 可在现有模型轮次中调用 `wait_for_followup`，默认每次最多 6 秒、最多 2 次，从本批第一条输入起的等待窗口最多 20 秒。等待持久化并释放处理线程，新输入可提前唤醒；完整消息正常回应。剩余时间放在本轮末尾的数据区，工具说明和声明保持稳定，不增加单独的分类模型调用。发送前发现同一人有新输入时，尚未产生副作用的轮次合并重算；已执行的动作保留回执并结束旧轮，由新轮接收后续消息，不能重放。群内不同主体独立排队，群聊只有实际触发回复的批次才纳入同主体未艾特的续句，原触发撤回后不再沿用。

输入明确区分 `current_message_id`（用户本条）与 `quoted_message_id`（本条引用的历史消息），并标注原作者。`reply_to` 默认指向要回应的用户消息，仍允许有意引用合法历史消息。仅含发送回执的缓存按可信的本地记录补齐作者；读取引用时核对会话、账号和消息，并复核读取期间的撤回。发送结构校验拒绝无效 ID 或一条消息中的多重引用，原有主人管理权限保持独立校验。

QQ 自主轮次提供可信当前会话，使用 `napcat_send(message=...)` 可直接回复，无需模型填写收件人号码。自主跨会话发送只接受同账号真实入站记录或实际成功查询的好友、群、群成员列表中的号码；正文和模型生成内容不作为号码依据。发送前校验实际路由（含转发与临时私聊的群回退），未知目标不会创建发送操作或不确定记忆。自主发送使用有最终回执的同步接口，异步及限速别名需改用对应同步动作；普通主人请求和本机调用保持原权限。

NapCat 的通用 `1200` 错误通常仍视为结果不确定。仅已核实的私聊发送前“无法获取用户信息”、且无任何成功数据的精确回执保留为 `failed/not_sent`；超时、断线、部分结果和其他异常继续禁止重发。失败回执也绑定原 `operation_id`，同编号重读不再发送，换参数会被拒绝且不能覆写原记忆证据。自主活动完成与消息送达分别判断，只有确认发送回执才能计入已联系用户。

等待参数为 `BINES_QQ_FOLLOWUP_WAIT_SECONDS=6`、`BINES_QQ_FOLLOWUP_WAIT_TOTAL=20`、`BINES_QQ_FOLLOWUP_WAIT_REQUESTS=2`；总窗口或次数设为 0 可关闭语义等待。等待窗口不包含模型计算耗时的保证，也不阻止接收窗口结束后新到达的消息。

独立的 Memory Worker 对所有渠道进行状态更新、情节总结、稳定事实提取和主人日记整理。默认每积累 40 条待整合消息，总结较早的 30 条；短会话也可在空闲后触发摘要。任务和重试保存在 SQLite 中，后台模型请求不占用对话进程。

摘要、日记和状态任务沿用 `DEEPSEEK_THINKING` 的思考模式，推理与正文共享输出额度。摘要和日记默认给 8192 个 token，状态更新给 4096 个 token；摘要与状态更新使用 JSON 输出格式。截断后仅重试当前请求，重试上限由 `BINES_MODEL_RETRY_MAX_TOKENS` 控制，默认 16384；状态任务自己的重试预算仍为 8192，并受全局上限约束。仍被截断或正文为空时按失败任务退避重试，保留原始消息，不把推理、半段 JSON 或空正文写入记忆；状态无变化必须由模型明确返回 `{}`。

检索键按源数据变化增量更新，状态、任务和用量写入不会触发整库重建；源消息变化会传播到依赖的检索键。向量只嵌入检索键，旧的整段查询接口从同一集合按来源去重。模型、实际revision、维度、tokenizer切片配置和预处理共同决定语义指纹，HNSW构建参数另外纳入索引指纹；变化时建立新集合，冻结初始变更和检索键水位，完成水位内构建后切换并继续补增量，再清理旧集合；已隔离坏片段不阻止切换，状态明确标记degraded。构建期间仍可用全文检索，不使用不兼容的旧向量。

在线向量维护把embedding与Chroma批次放在后台线程；SQLite仍由RPC线程独占，按来源版本和索引代次确认完成。每轮维护有10毫秒软预算和数量上限，单个数据库操作不能被预算强行中断。文档embedding默认每4条让出模型，前台查询优先，最多等待100毫秒模型锁；已有查询缓存无需等待。超时退回全文检索并记录busy，不能把busy解释为空结果。按语义指纹与实际文本hash缓存最多20000条向量，元数据或其他片段变化不会重算相同文本。坏批次二分隔离，逐键持久退避；永久错误或累计5次失败隔离，每小时探测，源版本更新可立即重试。在线rebuild-index返回排队状态，进度见stats.vector_status；离线维护仍同步处理完整重建。旧库首次初始化会扫描一次以建立变更跟踪。

原话与派生经历进入同一可恢复outbox，派生记录等待所引用原话确认；晚到原话会补齐同轮事件归属。单条失败按错误类型退避，多次失败进入隔离探测，不阻止独立会话；原始payload保留，新revision或显式retry可立即恢复。同步批次另有2秒软预算，单个RPC受其自身超时约束。

召回先按来源限制候选占用，并过滤不在有效期内的事实；向量候选不足时有限扩大。事实指定的原始来源优先于同段聊天背景。提示词保留实际命中的连续片段，引用回执对应实际展示内容。“为什么”本身不开启历史查询；明确历史问题才展示带生效、失效时间和当前状态的历史事实。

原话证据优先保留实际命中的消息，即使它位于同一轮对话的第四条之后；群聊证据随原文保留说话人的姓名与 ID。长原文围绕命中位置节选，跨渠道近期消息优先选择最新记录，再按时间顺序呈现。

上下文整理目标默认65536，兼容原有32768配置；每次文本模型请求的工具声明、调用和回执也计入。按实际展示的消息和片段去重，未展示的旧工作窗口命中可以作为召回证据补入，空闲分类额度可借给其他分类。历史和工具结果会按目标压缩；完整必需指令、当前输入和工具声明仍然保留，超过整理目标只记录诊断，不因此阻止任务。工具搜索先返回有界命中片段，原文用read_memory_source在当前scope内分页读取。可配置匹配模型的本地tokenizer；否则使用UTF-8字节上界，并明确记录计量方法，这不等于服务端精确token用量。显式设置BINES_MODEL_CONTEXT_TOKENS后，另行按总窗口扣除本次输出和协议余量，只有完整必需输入仍超过该硬窗口时才拒绝发送。

工具续轮只保留一组最新浏览器自动观察和最多两条历史样本；过期样本明确标作历史，文本按独立预算节选，保留来源、状态、采样时间与视频范围，不改写操作回执。时钟说明只保留一份，额外采样最多保留最近三次。完整观察仍写入原有经历记录。

QQ 与桌面的自主情绪和意图评估共用材料组装器：稳定规则、能力和来源资料在前，当前状态、活动、权限和时钟在后。重复证据使用正文范围引用，保留身份、有效期、纠错和检索命中；按分区预算选择历史材料，并明确标出节选或省略。不确定操作的目标和回执始终保留，避免因历史裁剪而重复执行。

自主活动支持独立等待队列 `waiting_activities`：定时暂停或较长观察间隔释放当前执行位置，期间可以选择其他兴趣，也可以保持安静。到期活动按等待时间轮转，恢复前重新评估；`pending` 仍只有一个，正在执行的轮次不会被另一个意图抢占。零延迟的人工验证或不确定回执暂停仍需主人恢复，主人全局 stop 会清空当前与等待活动。

普通聊天不会默认把暂停活动改成两秒后的 review；只有显式活动控制才更新该暂停。QQ 按活动 ID 合并所有未消费交接，桌面保留未确认的交接队列，旧检查点不能覆盖更高序号的进度。旧单活动状态会自然进入新队列。模型只接收最多八张等待意图的简短卡片，完整进度持续保存，不新增日额度或同时保存数量限制，也不额外调用模型来管理队列。

检索提供exact、association和explore模式：编号、原话等精确问题采用稳定直接检索；关联扩展同时考虑绝对激活和直接相关性；explore只用于显式自主探索且默认关闭，仅填空余名额。cold_activation_factor不是随机召回概率。

冷消息、冷情节摘要（episode）及符合条件的excerpt保留完整分片的全文索引。每个来源最多选择首尾两个紧凑原文片段作为语义代表，优先保留句界并按embedding模型的token窗口裁剪，不生成新摘要。独立archive通道结合全文与向量候选，默认最多补充3个独立冷来源；不再以热候选不足为前提。热向量查询在查询侧排除冷代表，避免大量档案耗尽热候选窗口；冷热候选随后按相关性和来源去重合并，同一查询复用embedding缓存。

冷全文候选在既有128个键的扫描窗口内保留到完整原文校验之后，再按来源去重和限额，避免URL近似片段或同源首分片提前挤掉真实匹配。显式引号内的片段优先作为精确线索，不以其中的短数字替代整段。扫描仍有上限，不保证排名在窗口外的任意原文片段必达。

冷热通道共用scope、时间有效性、撤回、纠错、audit_only与repair_pending校验，失效原文及其派生内容不能借归档通道返回。旧冷索引签名升级后按来源重新排入后台维护，分批补齐代表向量。首尾代表有数量限制，具体原话可走全文检索，泛化或换说法的问题仍受embedding模型能力与代表片段覆盖范围影响，不能据此保证全部历史细节都能被语义召回。

曝光只记录机会，不直接加权；经来源原文核验的引用产生有界正奖励，默认30天半衰期，未被引用不作为负例。衰减影响检索排序而非事实真假。每轮诊断分别记录主召回、画像、工具、向量busy/empty/error以及真正呈现的上下文，避免后一个查询覆盖前一个trace。

## 自动维护

- 真实完成的主人本机或私聊回合可触发自动纠错审查，范围限当前用户原话和本轮实际呈现的记忆。服务端核对身份、来源、版本和租约；第三方陈述、假设、时间变化或歧义不直接覆盖事实。
- 原始消息保留，纠错写入版本账本；统一解析消息ID、source_ref和派生记忆引用，用可重建反向依赖索引传播失效。纠错、撤回、修复和身份迁移共用来源规则，原始元数据仍是唯一真相。
- 默认12个建联候选每6个一页，同一任务持久续页，只有所有候选处理完才标记完成；已完成候选按版本保存，重试时复用。复用理由键同步更新正文、FTS与版本。建联使用紧凑证据编号和版本缓存；正、负判断均可缓存，缺失判断不当作负例。证据不足时自动扩大一次材料范围，仍不确定则保留未决记录，原文继续可检索。
- 紧凑建联输出格式、候选覆盖或证据校验失败时，将具体错误反馈给模型，最多立即纠正一次；仍失败则保留任务退避重试，不自动补齐负例或放宽证据要求。连接失败不会触发这次模型纠错。
- 确认的模型连接中断、超时及可恢复服务端错误使用独立计数，按 60、120、300、600、1800、3600 秒退避，之后每小时重试，不耗尽生成失败次数或自动恢复轮次。仅凭 `APIConnectionError` 名称不能判定网络故障：编码、参数、鉴权、配额和原因不明的错误仍有限重试。日志保留有界的原因类型链及状态码，不保存请求正文或凭据。记忆服务提交结果不明时仍由租约与完成状态核对，不能重新执行已完成写入。
- 迟到结果不能覆盖新租约。受信管理接口 `retry_failed_job` 可按任务 ID、scope、kind、领取次数、更新时间及原错误类型选择性恢复一个失败任务；保留单调领取凭据并记录恢复审计，不开放给普通聊天工具。管理页显示自动纠错任务及未决关联。
- 状态覆盖字段和物品增删按来源消息顺序生效，好感度增量按消息幂等；旧任务拿到新租约也不能覆盖较新状态。
- 后台记忆任务不设每日调用次数、每日 token 或单任务累计调用额度。2026-11-07 起移除相关配置与调用前拦截，旧配置不再生效；用量账本仍记录全部请求。
- 服务启动时自动释放旧的额度延期任务，以及因累计模型调用额度而终止的任务。保留来源、分页进度、生成失败次数和领取凭据；已完成、取消、正在执行及其他失败任务不受该迁移影响。同一任务默认最多恢复3次过期租约，避免失联执行反复重跑。
- 日记使用持久脏日期队列，每轮处理最多32天；旧库按持久游标每轮回填256条源记录。无关状态或任务更新不扫描全部历史日记，原有pending/running任务保留。
- 日记只整理已结束的日期，等待当日摘要、修复及本批来源的建联完成。摘要或日记等待建联依赖时每30秒重新检查，等待不计为生成失败，也不会调用模型。
- 日记输入为有界证据节选：独立保留对话摘要、同日原始交互和按活动合并的工具经历，默认正文预算24000 UTF-8字节。完整来源仍保留，失败和未确认状态不会被合并成成功。生成时固定人格快照并记录版本；同日原话变更会拒绝迟到结果。改写前的日记原文和元数据保存在`diary_revisions`，人格变化不会自动重写未进入脏日期队列的全部历史。
- 共享上下文、摘要和日记原话显式标记角色与参与者 ID，昵称不改变身份；原话中的第一人称按原说话人解释，发言人也不一定是所述事件的行动者。日记材料策略为 `diary-evidence-v3-attribution`。
- 日记正文保存前由独立模型请求对照同一份材料核对主体、对象和完成状态；不通过时带具体问题重写一次并重新核对，再次失败或核对不可用则进入原有重试机制，不保存草稿。正常增加一次后台请求，最多两次写作和两次核对（单个请求仍遵守截断重试规则），聊天不增加核对调用。新模型请求在有效领取凭据内延长日记租约，重复回执和过期任务不能续租。
- Worker 只在核对通过后生成绑定正文和材料摘要的回执，Server 校验后保存 `diary_attribution_review`。回执保证核对对象与落库对象一致；语义判断仍由模型完成，不能保证所有归属错误都被识别。已确认有误的日记可先标记 `repair_pending` 停止召回，走日记重生成路径；保存时归档旧版本并解除标记，不改写原始消息。
- 后台记忆任务按模型请求记录 Token 用量，包括截断、重试与失败；未知用量明确标记。该账本不覆盖全部前台聊天、视觉或搜索费用。

可在 `.env` 调整以下参数，修改后重启相关服务：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `BINES_MEMORY_ASSOCIATION_MODEL_CANDIDATES` | `6` | 单次建联送入模型的候选上限 |
| `BINES_MEMORY_RECOVERY_CYCLES` | `2` | 非临时传输错误的失败任务最多自动恢复轮数，设为 0 可关闭；不限制已确认网络故障的持续退避 |
| `BINES_MEMORY_RECOVERY_SECONDS` | `3600` | 自动恢复探测的间隔秒数 |
| `BINES_MEMORY_INDEX_BATCH_SIZE` | `64` | 后台向量维护每类操作的批次上限 |

## 可见范围

| 场景 | 记忆范围 | 个人状态 |
| --- | --- | --- |
| 本机桌面 | `owner`，与绑定主人私聊共享 | `owner` |
| 主人 QQ 私聊 | `owner`，可衔接桌面近期对话 | `owner` |
| 其他 QQ 私聊 | 机器人账号 + 用户 QQ | 同私聊范围 |
| 群聊 | 机器人账号 + 群号，所有本群公开发言 | 群范围 + 用户 QQ |

主人由 `BINES_OWNER_QQ_IDS` 显式绑定；群主或管理员角色不赋予主人身份。群内主人只读取本群公开记录。同一个用户在不同群、私聊的状态分别保存。远程记忆调用由网关从事件重新计算权限，模型传入的 scope 无效。

主人绑定或解绑时，按来源会话迁移原话、可证明归属的派生记忆、主体和状态效果。跨会话混合派生内容会失效并重新排入整理；不会把整个共享owner范围搬给单个QQ用户。无法证明来源的旧数据保留隔离，不凭猜测迁移。

新增个人事实的来源消息必须属于事实主体，模型把群成员 A 的原话归给 B 时不会写入 B 的画像。旧式无来源调用仅在单一真实用户且主体唯一匹配时兼容。

Memory RPC 默认监听 `127.0.0.1`，所有网络请求校验 `BINES_MEMORY_RPC_TOKEN`，未配置时在数据目录创建私有凭据文件。Docker 服务共享该目录；其他机器的客户端需要显式配置相同 token。管理页采用独立凭据、本机短期会话和 Host/Origin 校验，跨站页面不能调用管理 API；远程管理需配置允许的 Host 并携带 Bearer token。

撤回消息会替换原始正文并同步到记忆服务，同时失效其派生摘要和事实，并按有效来源重新计算相关个人状态。后续独立更新与明确同值确认保留；只继承的旧字段不算新来源。重算后保留干净的当前历史快照，重复撤回不重复累加或产生版本。未 @ 的群消息保留为公开背景。断线期间不能保证完整回放，会话下一次回复时补取历史。

完整模式可按需启动 RAG Web 管理记忆。离线迁移、校验或重建前停止 Memory Server、网关及其客户端；旧文件迁移使用 `python -m chatBot.migrate_memory`，保留原文件。当前没有自动删除保留策略。

## 历史分支合并与恢复

跨设备导入包与合并历史分支是不同操作。`.tools/memory_transfer.py import` 会替换整个记忆目录，当前设备已有数据库时默认拒绝；只有明确审阅整库替换后才使用 `--replace-existing`。需要保留双方新增历史时，使用 `thingking/scripts/merge_memory_history.py` 的计划、隔离验证、离线应用流程。

开始前停止所有数据库写入进程，保存完整SQLite备份及其WAL。`plan`只读检查源数据库/WAL/SHM的manifest哈希、候选内容、会话scope和owner身份绑定，并固定目标源数据表的基线；`stage`通过SQLite备份接口复制目标，只向隔离副本写入。审阅计划与副本后，`apply`才写入显式指定的目标。目标发生变化时必须重新生成并审阅计划，不能修改计划文件绕过基线校验。所有输出使用新文件名，工具会拒绝覆盖已有文件、输入数据库及其sidecar，包括新staging数据库的sidecar。

以下命令从仓库根目录执行，使用本机2026-11-09审计清单。示例输出目录必须尚不存在；重跑流程时换用新目录。

```bash
history_audit_dir=.tools/memory-persona-audit-20261109
history_source_db=.tools/memory_export/local-backup-20261022_111851/memory_data/memory.db
history_target_db=thingking/memory_data/memory.db
history_run_dir="$history_audit_dir/recovery-reviewed"
mkdir -m 700 "$history_run_dir"

python3 thingking/scripts/merge_memory_history.py plan \
  --source "$history_source_db" \
  --target "$history_target_db" \
  --manifest "$history_audit_dir/migration-candidate-source-manifest.json" \
  --candidates "$history_audit_dir/migration-recoverable-missing-candidates-private.json" \
  --output "$history_run_dir/plan.json"

python3 thingking/scripts/merge_memory_history.py stage \
  --plan "$history_run_dir/plan.json" \
  --output "$history_run_dir/staged.db" \
  --report "$history_run_dir/stage-result.json"
```

审阅计划、隔离副本及检索结果，确认目标仍停写且备份完整后，才执行应用：

```bash
python3 thingking/scripts/merge_memory_history.py apply \
  --plan "$history_run_dir/plan.json" \
  --target "$history_target_db" \
  --report "$history_run_dir/apply-result.json"
```

合并按来源分支、内容、scope、会话、时间、角色和actor去重。新消息分配新ID，旧`message_range`先在源库展开，再改为目标库的显式证据ID；摘要、事实和父记忆引用同步重映射，禁止按旧数字ID覆盖目标消息。目标中已撤回或删除的对应来源会阻断恢复及其派生内容。恢复消息标作历史归档，保留原日期和说话人；工具不调用模型、不创建整理任务，也不回放状态效果或新消息通知。应用后通过正常索引维护流程补齐检索投影，并复查scope内召回。重复应用同一有效计划新增0条，但报告仍须使用新文件名。

2026-11-09的隔离验证恢复了91条消息和4条记忆：85条未合并候选消息加6条摘要依赖，4条记忆中2篇情节摘要可用，另2条事实缺少明确主体的逐字原话证明，保留为`deleted=1`的历史待审核记录。它们不是已恢复的活跃事实。该次验证确认原有记录、状态和任务队列不变，91条消息有检索键，2篇摘要与3个会话范围的检索样例通过，未发生群聊内容进入owner范围；再次应用新增0条。数量仅描述这份来源分支及当时目标基线，不能视为任意备份的固定恢复结果。

实现入口：`chatBot/memory_hub.py`、`chatBot/store.py`、`thingking/qq_thinking.py`、`thingking/src/memory/`。
