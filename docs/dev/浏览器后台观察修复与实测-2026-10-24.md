# 浏览器后台观察修复与实测 · 2026-10-24

已修复“能读网页文字，但视频状态报窗口不可用”的问题。当前新启动的 Bines 专用 Chrome 在前台、后台和最小化时均能读取播放状态、变化的视频像素及页面截图。QQ Thinking 容器可以读取最新的自动观察结果。

问题有两个来源：

- Playwright 用管道控制浏览器，后台观察通过本机 TCP 连接读取。新启动窗口只有管道，导致文字快照成功，而视频观察无法连接。此前稳定性实测复用了带 TCP 的旧窗口，遗漏了新启动场景。
- 后台观察按页面的可见性和焦点选择目标，未与控制会话绑定。窗口状态变化或多标签可能导致目标缺失或不一致。

修复内容：

- 启动时同时启用 Playwright 管道和随机本机调试端口，并禁用浏览器后台节流。
- 每次成功的显式操作后，从控制会话读取 URL 和文档创建时间，准确绑定观察目标；相同 URL 的两个标签也可以区分。
- 观察始终读取绑定的标签，不需要把窗口移到前台。目标关闭、越界或绑定失败时暂停观察，不自动选择别的页面或打开新窗口。
- 页面身份同步失败不抹除已完成操作的回执。观察日志增加失败阶段，避免仅记录笼统异常类型。

另用系统状态核验，避免把网页的模拟焦点误当成窗口焦点：

- Finder 持续位于前台时，视频从 10.67 播放到 14.76 秒，像素变化。
- 窗口状态确认为 `minimized`，且 Finder 持续位于前台时，视频从 15.39 播放到 19.46 秒，像素变化。
- 两种状态下采样前后均未抢回窗口焦点。
- 已检查实际采样图片，内容为视频画面。
- QQ Thinking 容器通过现有 owner 权限上下文读到 1 条有效观察：状态 `ok`、包含 3 帧、播放推进为真；读取时观察约 18 秒前生成。

108 项网站相关回归测试通过，`git diff --check` 通过。镜像检查显示需要重建的服务为空。本次没有重建 Docker，也没有主动发送 QQ 消息。

原窗口尺寸、焦点和三个标签已恢复，浏览器桥继续运行。本次覆盖当前 B 站视频、新启动窗口及上述三种窗口状态；锁屏、系统休眠和受保护的视频内容未验证。首次测试以不等待快照的方式打开主页时，出现过一次截图超时，观察按设计暂停；后续视频页操作重新激活观察，连续采样正常。

日志中的 `memory-worker ... retrying invalid source quotes` 属于另一条链路：记忆建联模型提供的引用不是原文连续片段，worker 给一次纠正机会，再丢弃仍无法核验的关联。它不表示浏览器失败。
