# 缓存与调用成本优化

本次调整覆盖 QQ、桌面、自主活动、记忆整理和视觉调用。目标是提高相同请求前缀的复用机会，同时减少不值得付费的后台输入和请求。DeepSeek 服务端缓存仍由供应商决定，不能用本地前缀一致性推算实际命中率。

## 问题与处理

| 影响因素 | 调整 |
| --- | --- |
| 实时时钟、状态和召回内容位于前部，后续内容难以复用 | 固定工具规则和人设在前，历史随后，场景、状态、召回及本轮内容在后 |
| 续轮重建时间、网页观察、口吻位置 | 保存实际发送且经过裁剪的请求，追加工具响应和新的时间、观察；保留最新采样的明确语义 |
| 每轮滑动删除历史起点 | 默认保留 30 条起始历史，允许追加 10 条，再整体推进；每次读取原文，修订、撤回和权限隔离仍生效 |
| 经历摘要重复输入诊断、引用清单、候选快照 | 按字段投影，只输入意图、结果、失败状态、来源与纠错等摘要材料；完整回执仍保留 |
| 同活动大量碎片分别调用 | 同作用域、同会话、同日、同轮或同活动的来源最多 6 条合批，最多等 60 秒；逐来源核验回写 |
| 活动控制动作重复摘要 | `activity_continue`、`activity_pause`、`activity_finish` 仅留审计；活动进度仍按原流程保存 |
| 后台重试和重启放大调用 | 请求前事务预留自然日预算，返回后按实际用量核销，重启不清零；合批失败自动拆回逐条重试 |
| 流式和视觉调用缺少完整统计 | 独立统一账本记录逻辑请求、API 用量和缓存回执；未知用量单独标注 |
| 相同图片反复分析 | 仅对可信调用方授权的同作用域、同来源、同任务和相同内联图片复用完整描述，最多 128 项、120 秒 |

普通建联沿用此前默认检索线索的实现；需要模型判断的建联还受独立额度限制。

## 默认后台额度

按 `BINES_MEMORY_TIMEZONE` 的自然日计算，默认 `Asia/Shanghai`。达到任一额度后将任务延到次日，保留原始数据，不增加生成失败计数，前台聊天不受该后台额度限制。

| 后台类别 | 调用上限/日 | 输入 + 输出 token 上限/日 |
| --- | ---: | ---: |
| 建联 | 100 | 300,000 |
| 摘要、日记、审查、修复 | 300 | 1,500,000 |
| 状态更新 | 1,000 | 2,000,000 |

配置项见根目录 `.env.example` 中 `BINES_MEMORY_*_DAILY_CALLS`、`BINES_MEMORY_*_DAILY_TOKENS`。额度不是供应商账单的精确硬上限：调用前使用保守输入估算加输出额度，调用后以回执核销；缺少回执时保留预留值。reasoning token 已包含在 completion token 内，不重复相加。当前日期的旧任务账本会被纳入迁移后的预算，因此上线当天可能立即延期已有积压。

## 查看实际命中率

所有模型进程共用 `BINES_MEMORY_DIR/model_usage.db`；可以用 `BINES_MODEL_USAGE_PATH` 改位置，但必须配置为共享路径。

```bash
docker exec bines-qq-thinking-1 python -m common.model_usage --hours 24
```

按任务和模型展示请求数、输入、输出、缓存命中比例、未知用量次数。命中比例是已返回缓存字段的请求中“命中输入 token / 输入 token”的加权结果，不是命中请求占比。没有缓存字段的供应商响应保持未知；流式请求读取最终 usage chunk，提前中断不会记成零消耗。

`MemoryService.stats()` 的 `model_usage_24h` 返回同一份聚合结果。后台 `memory_model_calls` 是预算和任务审计镜像，使用同一 `call_id`，不能与统一账本累加。统计不保存提示词、回答、身份信息或凭据。网络错误缺少回执、SDK 内部传输重试等情况不能靠本地统计完整还原账单，应保留供应商账单核对。
