# 浏览器卡死修复与实测 · 2026-10-24

本次直接修复正在使用的 Bines 主浏览器。Chrome 原进程与登录目录保留，宿主机浏览器桥原地恢复，未重建 Docker。

20:18 左右，直播播放停止，Chrome 的 `/json/version` 和 `/json/list` 同时超时。只终止 agent-browser 0.27 控制进程、保留 Chrome，两个接口立即恢复响应。这证明本次故障与控制连接相关；仅调整截图方式不足以解决。

上游 [agent-browser 0.39.2 发布说明](https://github.com/vercel-labs/agent-browser/releases/tag/v0.39.2) 包含 CDP 网络暂停事件丢失修复（#2110），与该故障相符。但未捕获到旧运行时的事件丢失计数，因此不将具体队列分支当作已证明的唯一原因。

尝试新版时，实际发现它拒绝 `--allowed-domains` 与持久 profile/CDP 连接组合。最终采用官方 0.19.0 的 Playwright 控制实现，保留平台域名过滤与持久登录，避开旧 Rust 控制路径。宿主机 Node 18 还会产生 `value.isWellFormed is not a function`；现在自动选择 Node 22 或更新版本，本机实际使用 Node 24.19.0。没有合适版本时，会安装项目专用 Node。

代码调整：

- `website_runtime.py` 固定兼容的控制实现，拒绝不兼容的系统/自定义版本与显式 Rust 模式，并检查 Node 版本。
- `common/website.py` 首次操作优先连接同 profile 的现有 Chrome。选定连接后固定该模式，连接失效不会改为启动替代窗口；新建的自有会话保持 profile 模式。
- 保留平台域名限制、元素引用校验、操作回执与后台只读观察边界。
- 兼容 Playwright 运行时的数字标签编号，继续向模型提供 `tN`；清理控制台颜色转义。

真实主窗口验证：

- 通过 Bines 浏览器桥查询标签、按 `t0` 切回直播、刷新原标签，均返回成功。
- 刷新后直接读取视频：`paused=false`、`readyState=4`，播放重新推进。
- 运行时访问 `https://example.com/` 被域名限制拒绝，直播地址保持不变。
- 自动视频观察在真实页面恢复，持续发布视频观察结果。
- 20:37:36–20:50:41，原 Chrome 进程持续运行超过 13 分钟，控制接口没有再次卡住。32 次 CDP 检查的中位耗时为 1.6 ms，最大为 16.4 ms。
- 原节目在 20:45 左右正常下播，页面显示“未开播”，弹幕讨论节目结束。下播前连续 7 分 40 秒取得 24 次有效视频像素采样；视频元素消失属于直播结束，页面与后台观察仍正常。
- 同一窗口随后切换到正在播放的赛事直播，连续 2 分钟取得 7 次有效视频像素采样，视频一直为 `paused=false`、`readyState=4`。
- 长时运行后再次刷新成功，视频进度从 0.95 秒推进到 4.14 秒，最终浏览器桥为 `ready`，故障记录为空。
- 已清理本次诊断新增的 3 个空白窗口，原有 5 个标签保留。

回归验证：浏览器服务、CDP 只读观察和自动观察共 102 项测试通过；补充覆盖运行时版本选择、旧 Node 避让、现有窗口连接、拒绝替代窗口、自有 profile 模式与 `tN` 兼容。

Docker 镜像检查的待重建服务为 `[]`。既有构建进度改动保留，6 项构建进度测试通过。

验证范围为本机实际 Bines 主窗口、B 站直播及相应回归测试；未扩展为所有网站或无限时长稳定性的保证。
