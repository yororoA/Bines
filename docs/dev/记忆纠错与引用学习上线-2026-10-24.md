# 记忆纠错、证据归并与引用学习上线

四项改动已接入实际服务，管理页面为 http://127.0.0.1:5001，记忆星图继续使用 http://127.0.0.1:5001/constellation。星图打开记忆详情后，可以使用同一套纠错入口。

## 行为变化

| 功能 | 当前行为 |
|---|---|
| 事实纠错 | 提交原文片段、正确内容和依据；记录不可覆盖的操作账本，保留原始消息及旧版本。受影响的关系立即失效，派生摘要暂停召回并重建。 |
| 理由纠错 / 拒绝 | 校验节点与理由版本，暂停旧关联，重新评估。拒绝的理由键不能被迟到结果或后续建联恢复。新理由不会继承旧理由的引用份额。 |
| 同事件归并 | 原始来源仍分别保存；可信 journal 命名空间与同一回合的回执、续接、对话和摘要，共用一份独立证据身份。它们不能互相强化，也不会重复占用引用和 TopN 留存份额。 |
| 上下文链间竞争 | 检索时冻结实际呈现的节点、版本与理由。只有答案中确实出现、原文引用通过校验的引用，才学习该查询下的理由份额；仅检索、呈现或建联不会学习。 |
| 建联提速 | 默认 4 条建联线程，加 1 条处理状态、摘要、日记与纠错重建的线程；有任务时连续领取。无候选免模型请求；经历先摘要，再只为稳定版本建联。 |

普通 QQ 会话不获得任意记忆修改权限。模型的事实纠错工具必须绑定真实主人消息、已实际呈现的来源及不可变权限上下文；自主回合、非主人私聊和群聊均不能借此修改主人记忆。

## 真实模型比较

在 SQLite 一致性备份的隔离副本上，使用 3 组真实历史回合、同一 `deepseek-flash` 配置比较。旧代码基线为 `d95eb69`。旧流程使用原建联提示词、最多 20 个候选、约 2800 字材料及最多 40 条理由；新流程最多 12 个候选、约 1400 字材料、16 条理由、关闭建联请求的 thinking，并限制输出与重试预算。

| 指标 | 旧流程 | 新流程 |
|---|---:|---:|
| 单任务中位耗时 | 41.003 秒 | 4.344 秒 |
| 三组累计输入 Token，含重试 | 74,991 | 26,532 |
| 三组累计输出 Token，含重试 | 16,734 | 1,972 |
| 实际请求次数 | 4 | 3 |
| 通过原文引用核对的关联 | 0 / 5 / 5 | 0 / 6 / 4 |

该小样本中，中位耗时降低 **89.4%**，输入 Token 减少 **64.6%**。这里统计实际请求执行时间，未使用历史排队时间代替模型耗时。

实测还发现，图片内容未知时，模型可能因同一发送者多次发图而建立弱关系。已补充判断要求，最终该样本与旧流程一样输出零关联。模型仍自主选择有效关系，不要求凑满 6 条。

原文校验失败时给予一次有界修正机会；修正后只保留逐字引用通过的条目，丢弃的数量进入任务记录。程序不修改引用、不补造证据。一条坏引用不会迫使其他合格关联随整个任务重新排队。

这些结果验证请求成本与引用的原文一致性，不能证明所有关系在语义上都正确，或代表所有长期任务的速度。

- 原后台运行约 271 秒的观察窗口中，完成 **205 个建联任务、50 个经历摘要**。其中 60 个建联任务无候选，未调用模型；其余建联的执行耗时中位数约 5.57 秒。观察窗口包含一次修正发布及服务重启，不能视为长期吞吐承诺。

## 维护与边界

管理页面的完整记忆区提供“纠正事实”，每个理由下提供“纠正理由”和“拒绝理由”。下方显示纠错历史、同事件来源、查询理由份额及实际任务耗时。版本冲突时保留输入，要求重看当前版本后重新判断。

当前上下文学习采用同作用域内的精确归一化查询，尚未泛化到近似问题。缺少可信回合身份的历史记录保持独立，不按 URL 或话题强行合并。数值等无法从纠正句安全还原的单值事实暂停事实 API 输出；来源已不存在的派生记录保留旧文供审计并暂停召回。

历史积压仍在后台处理，不需要等全库完成才能使用新功能。后续应观察真实引用质量、模型原文引用失败比例和持续运行的吞吐。
