# 关联记忆第二轮优化与验证

本轮将同一次查询的来源读取与校验合并，并在排序、去重后才生成最终证据。固定语料回放中，查询中位耗时从 **377.2 ms 降至 70.9 ms（降低 81.2%）**，Evidence Recall@10 保持 **0.738**。自动冷却仍关闭，生产记忆库未写入改动。

这个对比使用优化前的记忆模块代码快照与当前代码，在同一份冻结 SQLite 语料的独立临时副本上执行。两种实现均先完整预热一遍，再对每个问题重复 5 次，共计每种实现 105 次计时查询。28 个旧标注中有 7 个来源或原文已失效，未补造标签；比较使用同样的 21 个剩余问题，其中 14 个有答案、7 个无答案。

本次使用词面检索，没有调用模型或生成新关联，没有加载真实向量模型，也没有执行 TopK 冷却。延迟是本机语料的描述值；结果验证性能与接入兼容性，不能证明真实建联收益或答案忠实度。无答案问题仍会返回候选，后续需要拒答与忠实度评测；检索到资料不能视为问题已有可靠答案。

本轮代码还完成了这些修正：

- **来源缓存**：缓存只存在单次请求内，检测同连接的 `total_changes` 与外部写入的 `data_version`；来源修改或撤回后重新读取。补齐 memory_id、node_id 查询索引，避免全表扫描。
- **证据生成**：只为最终选中的候选取证；冷摘要可以沿关联读取原始证据，继续退出直接索引。删除、撤回、scope 和时态过滤保持优先。
- **独立计权**：引用只能归属本轮确实呈现的理由。单一理由自动归属，多理由允许指定 chain_id；无法归属的事件保留审计，不强化所有链。旧计权缓存自动失效，来源与事件保留。
- **建联材料**：查询使用真实正文，排除当前节点及同源派生材料；说话者头部不会制造候选。长材料保留匹配查询的尾部原文，引用仍须通过原文校验。
- **有效关联**：零置信度与来源版本过时的关系不参与激活。失效成员不占用有效候选额度；没有有效理由时按内容先验和真实使用进行后备评分。

验证结果：**294 项完整单元测试通过，包含 44 项关联测试；50 项网关/经历记忆协议测试通过；git diff --check 通过。** 新增覆盖缓存复用、外部撤回、冷摘要、按理由引用、隐藏理由拒绝、旧缓存恢复、长文尾部、零置信度、失效关系及候选额度等边界。完整回归使用临时 Python 环境和 Chroma/FakeEmbedder；协议验证没有真实 QQ 登录。
