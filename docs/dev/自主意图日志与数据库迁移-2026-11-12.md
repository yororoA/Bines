# 自主意图日志与数据库迁移

已部署到本机 Docker 链路，8 个服务健康，真实 QQ 连接及 worker 探针通过。

## 日志

QQ 调度器分别记录自主任务执行中、自主任务待执行、用户消息待处理、QQ 连接断开和其他事件待处理。多个阻塞同时存在时，主原因按连接、用户消息、自主任务顺序显示，并保留各类任务的执行数、排队数及从入队起的持续时间。

去重依据原因、连接状态、队列编号与执行状态；时间自然增长不会每两秒打印相同日志。继续保持同一会话串行执行，自主任务占用通道时不会再笼统报告“会话忙碌或连接不可用”。

部署后的在线记录已出现“自主意图门控 · 启动缓冲 · 120s 启动缓冲”。执行、排队、断连以及组合状态通过隔离回归验证，未向真实 QQ 注入测试消息。

## 存储与迁移

- 默认 Docker 后端为 Redis。QQ/桌面调度、冷却、权重、兴趣、意图队列、门控、活动进度，以及桌面交接和主人暂停控制使用持久文档。
- 独立卷 `bines-autonomy`，开启 `appendonly yes`、`appendfsync always` 和 `noeviction`，状态没有过期时间。调度租约单独过期并自动续期。
- 文档带版本号；旧版本覆盖会失败并要求重新加载。调度租约阻止第二个调度器同时执行。Redis 不可用时暂停自主调度，不切换后端；暂停控制读取失败不能视为允许继续。
- 自动从旧 `proactive_sessions`、`proactive_desktop.json`、`desktop_activity_handoff.json`、`autonomy_control.json` 初始化缺失文档。旧数据保留、不再双写；已初始化的空状态也不会反复导入旧资料。
- QQ 消息、执行队列、回执与交接事务仍在 `gateway.db`。交接先保存 Redis 状态及 `handoff_ref`，再确认 SQLite 队列；中途退出后根据引用跳过已应用的记录。
- 纯宿主模式未配置时使用显式 SQLite 后端；配置 Redis 时断连也不会回退。宿主默认连接 `127.0.0.1:6380`，容器连接 `redis:6379`。

本次部署冻结旧调度器后备份网关数据库，逐项核对并迁移 1 个已有 QQ 会话。在线验证确认 Redis 文档版本持续增长，旧状态表与快照相同。

Redis 首次创建空卷时曾因镜像复制目录属主导致启动失败。已对数据卷设置 `nocopy: true`，初始化服务负责设置属主和权限；修复后通过健康检查与独立新卷回归。

旧回归中一项断言将每轮新增时间提示当成最后一条工具结果，已改为根据 `role=tool` 与 `tool_call_id` 定位结果，继续验证无效 JSON 会反馈给模型。
