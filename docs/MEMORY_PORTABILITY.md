# 记忆导出与迁移

在模块管理页或记忆管理页点击 **Bines 状态与迁移**，可查看服务、记忆、后台任务和模型用量，并下载完整记忆包。默认入口为 `http://127.0.0.1:5000/status` 和 `http://127.0.0.1:5001/status`，端口以本机配置为准。Docker 使用记忆服务提供的 5001 入口；5000 需要启动宿主机管理器。

## 选择导出方式

| 方式 | 用途 | 内容 |
| --- | --- | --- |
| 可读 JSON | 阅读、分析或按作用域分享 | 有效记忆、经历，以及选择 owner 时的当前状态；不是可恢复备份 |
| 完整记忆包 ZIP | 换机器、保存可恢复快照 | 完整 memory.db、版本、SHA-256 和所有数据表计数 |

完整记忆包包含已同步的原始对话、各类记忆、身份映射、动态状态、生命记录、纠错与历史、关联关系、记忆整理任务账本。它通过 SQLite 在线备份接口读取一致快照，包含已提交的 WAL 数据；导出不停止服务，也不直接复制活动数据库文件。

**记忆包不是整个 Bines 的运行环境备份。** 包中不含 `.env`、API Key、管理/RPC/Redis 凭据、人格文件、模型、媒体、浏览器和 QQ 登录态、其他 SQLite 数据库、Redis 自主活动状态或 Chroma/Qdrant 索引。`gateway.db` 中尚未同步到记忆库的消息也不在包内；换机前请在状态台确认 QQ 同步与后台任务情况。各数据库不存在跨服务的统一快照。

记忆包含完整私人内容，未加密。使用私有存储和安全传输；文件的 SHA-256 用于检查损坏，不证明来源身份。

## 导出与检查

状态台的“下载记忆包”提供 ZIP 下载。“选择记忆包 / 校验”只检查文件，不写入当前记忆库。网页检查上限为 512 MiB，较大文件使用命令行。所有网页接口沿用管理页的本机会话或 Bearer 鉴权。

在项目根目录运行以下命令，无需加载嵌入模型：

```bash
python thingking/memory_admin.py export-bundle /安全目录/bines-memory.zip
python thingking/memory_admin.py inspect-bundle /安全目录/bines-memory.zip
```

导出文件必须不存在；源库默认来自 `BINES_MEMORY_DIR`，也可传 `--db /路径/memory.db`。`--timeout 30` 限制 SQLite 快照的等待时间。导出与检查会验证格式版本、大小、SHA-256、SQLite 完整性、外键和表计数；当前支持的数据库大小上限为 16 GiB。输出包含范围说明与计数，不打印记忆正文。

## 迁入新机器

1. 在新机器安装同一版本或兼容版本的 Bines 及依赖，暂不启动服务。把 ZIP 安全传到新机器，执行 `inspect-bundle`。
2. 选择**不存在或完全为空**的目录，导入：

   ```bash
   python thingking/memory_admin.py import-bundle /安全目录/bines-memory.zip --target-dir /新路径/memory_data
   ```

   导入会先在临时目录验证全部内容，再发布 `memory.db`；不会覆盖、合并现有数据，也不会启动服务。失败不会替换当前记忆库。若目标已有文件，请另选新目录，不要为绕过保护删除原库。

3. 宿主机模式：在 `.env` 设置 `BINES_MEMORY_DIR=/新路径/memory_data`。Docker 模式：Compose 固定挂载宿主机 `thingking/memory_data`；应先停止旧实例并保留原目录，再将校验后的新目录放到此位置，或显式调整 Compose 挂载。仅修改宿主机 `.env` 中的路径不会改变 Compose 挂载。
4. 单独恢复必要的人格定义（`thingking/persona/persona.yaml`）和配置，重新配置凭据。保持主人绑定、时区等身份相关配置一致，避免启动时触发意外身份迁移。网关与 Redis 运行数据若需保留，须单独制定停机备份与恢复计划；不要把旧发送队列当作记忆包自动恢复。
5. 启动 Bines，打开状态台核对记忆数、服务和索引状态。索引由现有维护流程重建；需要手动重建时用记忆管理页按钮，或停止服务后运行 `python thingking/memory_admin.py rebuild-index`。记忆整理任务及租约原样保留，依现有恢复机制继续执行。

回滚时停止新实例，切回保留的原数据目录及配置，再启动。回滚不会合并在新实例产生的历史；需要保留两边新增内容时，使用 `thingking/scripts/merge_memory_history.py` 的计划、隔离验证和离线应用流程。

## 旧格式与旧脚本

旧 JSON 文件迁移继续使用 `python -m chatBot.migrate_memory`。历史 `.tools/memory_transfer.py` 生成的 `.tar.gz` 是另一种整目录归档，不接受新版 ZIP 校验，也不能充当新版记忆包。该脚本会携带目录中的凭据、备份等运行文件，且不涵盖 Docker 独立命名卷；新备份请使用本页的 `export-bundle`。不要把历史归档当作可以公开分享的文件。

## 状态台的含义

状态台通过各服务的只读探针和既有记忆 API 汇总信息，不会启动或停止服务。某个组件不可用时，其他面板继续显示；“未连接 / 不可用 / 未知”不会被显示成健康。5001 没有宿主机进程管理器时，不把缺少进程信息判定为所有服务停止。服务管理、详细记忆与星图仍通过原入口操作。
