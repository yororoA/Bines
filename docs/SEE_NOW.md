# See Now 屏幕与视频感知

实时屏幕模块持续采样主显示器，在本地使用 See Now 筛选变化帧、组合成拼图，再交给 Bines 已配置的视觉模型。Thinking 接收带采样时间的文字观察；发声、人格和记忆继续使用 Bines 原有链路。原始截图和拼图不写入生产日志或结果文件。

## 九宫格视频观察

实时屏幕、浏览器视频、摄像头、QQ 收到或引用的视频，以及本地视频文件，共用 See Now 的变化筛选。每张图固定 3 行 3 列，入选画面按采样时间从左到右、从上到下编号。满 9 帧输出一张，实时刷新、超时或文件结束时可以提前输出。空格留白。默认 1260×720 的拼图每格约 420×240，可结合按需截图核对细字。每格保留时间和位置，所有入口只分析画面。

| 入口 | 默认行为 |
| --- | --- |
| 实时屏幕 | 启用后每秒采样 4 次，首次观察立即出图，随后按变化和间隔刷新。 |
| 浏览器视频 | 主动观看默认 6 秒采 9 次，可选 1–30 秒、2–36 次采样。自动观察默认 4 秒采 9 次。每张图最多 9 个入选画面。可见字幕按采样时间提供给模型。 |
| 摄像头 | 在已启动的摄像头服务中每秒采样 4 次。收到观察请求时使用最近 10 秒的画面，含最新采样，请求最多交付两张图。 |
| QQ 视频 | PyAV 使用 FFmpeg 解码，目标每秒采样 4 次，每段最多 240 个候选、8 张拼图。保留原有会话和撤回校验。 |
| 本地视频文件 | PyAV 流式解码，默认每秒采样 4 次，最多 2400 个候选、120 张拼图。每张分别分析并显示时间范围。 |

文件视频达到采样上限时会沿全片降低采样密度。达到拼图上限且后面还有拼图时，结果会说明分析到哪一秒。解码像素预算用完时，已经采到的画面仍可分析，结果会注明最后采样时间。可按需调整本地文件预算，例如：

```bash
python video_analysis_standalone.py --video clip.mp4 --fps 4 --max-sheets 30 --output result.txt
```

## 启用与依赖

在现有模块管理页打开“实时屏幕分析”，保存启用。原有开关保持有效，纯 ChatBot 模式仍不启动桌面采集。未启用时不会自动采屏。

屏幕采样依赖 thinking 环境中的 mss 和 Pillow，各路视频筛选使用 Node.js 20 或以上。本地及 QQ 文件解码使用 PyAV 随包提供的 FFmpeg 库。筛帧模块随源码固定版本提供。原生安装器会为 launcher、thinking 和 visual 环境检查 Node，缺失时尝试安装到项目已有的网站运行目录。`--check` 只检查依赖。使用 Docker 运行 QQ 时需要重建对应镜像，镜像内提供 Node。

可先单独检查屏幕运行依赖（不截图、不调用模型）：

```bash
python realtime_screen_analysis_standalone.py --check
```

`BINES_NODE_BINARY` 可在 `.env` 指定 Node 可执行文件的绝对路径。未指定时查找 PATH、项目网站运行时、NVM 和常用安装位置；无兼容版本会明确报错。macOS 需要为实际启动 Python 的应用授予系统屏幕录制权限。

## 参数与回退

参数保存在 `server/realtime_screen_config.json`，缺失字段会补默认值。管理页保存开关和间隔时保留其他参数。

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | `false` | 实时采样开关 |
| `backend` | `see_now` | 新筛帧拼图；设为 `legacy` 可回退到 pHash 与三帧拼接采样 |
| `capture_fps` | `4` | 本地每秒采样次数，范围 1–12；采样不等于模型调用 |
| `interval_sec` | `10` | 两次自动视觉请求的最小间隔，范围 3–120 秒；明确刷新请求可提前执行 |
| `quality` | `high` | `low` 798×450、`standard` 1050×600、`high` 1260×720 |
| `result_ttl_seconds` | `90` | 按采样时间判断结果有效期，范围 15–300 秒 |
| `min_change_ratio` | `0.15` | 仅用于 `legacy` 的变化阈值 |

屏幕按比例缩放并补边，保留画面边缘。拼图的每格可能缩小文字；需要细字或指定区域时，Bines 仍可主动重新截图；该工具沿用现有固定缩放，不保证逐字 OCR 准确。配置变化会重建采样会话；停用后旧的模型请求即使返回，也不会恢复旧观察。

回退模式继续使用结构化结果、有效期和同一视觉客户端，不恢复旧文本缓存的“永久最新”行为。若采样或 Node 启动失败，服务报告失败，按需截图入口仍保留，不静默切换实现。

## 时效与资源边界

采屏和模型请求分别运行，视觉模型处理期间继续采样。输入队列和待处理拼图都有上限，拥塞时保留较新的画面，因此这是画面抽样，不是完整录像。观察不能替代操作成功回执，也不包含声音。

`server/realtime_screen_observation.json` 只保存采样时间、帧元数据、分析文本和服务状态；文件已从 Git 排除。读取方校验有效期和生产进程存活，失败、过期或旧格式文本不会被当成最新画面。屏幕内容被标为外部资料，不授予工具权限；桌面观察仅注入可信身份的对话。

视觉请求走现有 `vlm_client.call_vision`，沿用凭据和 usage 统计。费用以服务商返回的 usage 为依据；增加采样率、扩大拼图或缩短间隔可能增加成本。没有固定的节省比例保证。

## 源码与验证

[九宫格与五类入口的验证报告](tests/see-now-unified-video/index.html)记录了浏览器字幕、受控摄像头和文件解码实测。聊天和本地文件入口使用同一段 MP4 对照，实际输出见[九宫格示例](tests/see-now-unified-video/evidence/grid-01.png)。

See Now 来源、固定 commit、文件校验值与局部适配记录在 `vendor/see_now/SOURCE.json`。保留 Apache-2.0 的 LICENSE 与 NOTICE。生产桥只加载筛帧、排版与 PNG 编码模块，不启动原 DSH 会话、悬浮窗或音频功能。

隔离回归（生成测试图，不使用私人画面）：

```bash
python -m unittest verification.see_now_bridge verification.screen_observation verification.screen_runtime -v
```

真实浏览器录屏的回放工具在 `verification/record_screen_fixture.mjs` 和 `verification/screen_replay_benchmark.py`，使用同一素材比较旧采样和 See Now。改为固定九宫格前的对照结果见[旧版验证目录](tests/see-now-screen/index.html)。真实视觉模型测试只发送受控测试素材；报告区分采样遗漏、图片文字可读性、拼图延迟、模型耗时与服务商返回的 token。
